Home / Self-hosting

Run it on your infrastructure

Your workspace. Your model endpoint. Your data boundary.

ARGUMENTUM is designed for local and researcher-controlled deployment. The GitHub Pages website is static documentation; the interactive workspace runs from the self-hosted FastAPI service.

Requirements

Prepare your environment.

  • Python 3.11 or later for package installation and command-line tools.
  • Docker Engine and Docker Compose for the full service stack.
  • A compatible model endpoint and credentials for non-demo research runs.
  • Unique secrets and a suitable access policy before exposing the service to a network.
Quick start

Install the project.

The following commands mirror the repository's installation and self-hosting instructions.

git clone https://github.com/voyager67/Argumentum-Research-engine.git cd Argumentum-Research-engine python -m venv .venv # macOS / Linux: source .venv/bin/activate # Windows PowerShell: # .venv\Scripts\Activate.ps1 python -m pip install -e ".[dev]" argumentum doctor argumentum agents
Run the service stack

Configure, then start.

cp .env.example .env # Set unique secrets and model settings in .env first. python scripts/init-selfhost.py docker compose --profile ollama up --build -d

Researcher workspace

After the service starts, open http://127.0.0.1:8080/ui in your browser and connect with a workspace bearer token.

API documentation

The API schema is available at http://127.0.0.1:8080/docs on the local service.

Before production

Keep deployment boundaries explicit.

  • Change all default and generated secrets appropriately; never commit .env or credentials.
  • Use TLS, authentication, rate limiting, backups and an institutional access policy before network exposure.
  • Review model-provider privacy terms and the handling rules for researcher-supplied documents.
  • Validate sandbox isolation before enabling the optional experiment worker.
  • Verify sources and generated claims independently before scholarly use.
The public GitHub Pages site does not contain the API, database, queue, model server or authenticated workspace. Those components must be deployed separately using the repository instructions.
